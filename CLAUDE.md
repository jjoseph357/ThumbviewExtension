# Guidance for Claude Code

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. See [DESIGN.md](DESIGN.md) for the design rationale behind the architecture and behavior decisions described here.

## Keeping documentation current

Every change must update all affected documentation before the task is complete. Stale documentation is actively harmful.

- **CLAUDE.md.** Update when architecture, module responsibilities, config keys, or conventions change.
- **DESIGN.md.** Update when a design decision changes. Explain the technical reasons behind architecture decisions so maintainers understand tradeoffs.
- **CHANGELOG.md.** Update for every release following Keep a Changelog guidelines.
- **README.md.** Update when commands, features, or the development workflow change.
- **CODEBASE_OVERVIEW.md.** This is a dated audit snapshot marked "re-verify before relying on specifics", not living documentation. Do not update it for routine changes. Touch it only if a change falsifies one of its specific claims, and prefer noting the document as stale over rewriting it wholesale.
- **In-code comments.** Update file-level and inline comments when the behavior or structure they describe changes.

## Code comments

Follow the global no-comments-by-default rule (comment the WHY, never the WHAT). On top of that, follow these project conventions:

- **Top-of-file summary.** Add 1 to 2 lines on the pure-logic modules (`scanner.ts`, `layout_core.ts`, `spanning_layout.ts`, `state.ts`) and on `media/overview.js` explaining what the module computes and what it returns to its caller. `extension.ts` does not need one because its command registrations are self-orienting.
- **MARK-style section comments.** Used in `media/overview.js` on the top-level render and event-handler blocks (`render()`, `mousedown`, `mousemove`, `mouseup`) for navigation. Do not introduce them elsewhere unprompted.
- **Shared layout code.** Pure layout functions the webview also needs belong in `src/layout_core.ts` (no imports), then `npm run sync-core` copies them into the generated block at the top of `media/overview.js`. Never edit that block by hand and never re-add a hand-kept copy. Anything still duplicated by hand (`buildSpanningGrid`/`buildSpanningGridLocal`, the search regex) needs a one-line comment at each copy pointing at its twin.

## Commands

```bash
npm install          # install dependencies
npm run compile      # sync-core, tsc src/ -> out/ (types, tests), esbuild bundle -> dist/extension.js
npm run watch        # esbuild watch (also re-syncs the layout_core block) + tsc -watch (the F5 build task)
npm run sync-core    # regenerate media/overview.js's layout_core block after editing src/layout_core.ts
npm run check-core   # fail if that block is stale (CI)
npm run screenshots  # re-render README images (media/screenshots/) headlessly from a fresh demo workspace
npm run lint         # eslint over src/
npm run test:unit    # run the node-based unit test suite
npm run test:a11y    # axe-core audit of the real webview page in headless Chrome
npm test             # integration tests inside a downloaded VS Code (src/test/integration; needs a display, CI uses xvfb-run)
npm run benchmark    # webview timings at 1k/5k/10k synthetic files in headless Chrome
```

### Running the extension while developing

Pressing `F5` starts the `watch` build task and launches an Extension Development Host window with Thumbview loaded. Pressing `F4` in that window opens the minimap panel. It does not hot-reload. Relaunch `F5` to pick up compiled changes. A full walkthrough is in README_DEV.md.

### Packaging

Packaging is situational, not everyday development. See README_DEV.md's "Package and install a `.vsix` locally" section (`npm run package`). Only `dist/extension.js` and `media/` runtime files ship (`.vscodeignore`); `package.json` `main` is the bundle, not `out/`. The source repository is private, so `package.json` has no `repository`/`bugs`/`homepage` links (feedback goes to the Marketplace Q&A tab) and README images load from the public `jjoseph357/thumbview-assets` repository: always package and publish through `npm run package` / `npm run publish:marketplace`, which pass `--baseImagesUrl`, and push new screenshots there with `npm run publish-assets`. CI (`.github/workflows/ci.yml`) runs check-core, lint, test:unit, test:a11y, the integration tests, the benchmark, and `vsce package` on Linux, and test:unit on Windows and macOS for pull requests and `main`. The demo workspace used by the headless scripts and integration tests comes from the tracked `scripts/generate-demo-workspace.py` (`demo-workspace/` itself is gitignored).

## Architecture

Thumbview is a VS Code extension that renders every workspace source file as a syntax-highlighted minimap tile in a grid. Two runtime halves communicate over `webview.postMessage`: the extension host (Node, TypeScript, bundled by esbuild to `dist/extension.js`; `tsc` also emits `out/` for type checking and tests) and the webview (browser JS, `media/overview.js`, unbundled).

```
extension.ts (host)
  ├─ listWorkspaceFiles()    [file_discovery.ts]  per workspace folder: `git ls-files --cached --others --exclude-standard` (trusted, file scheme),
  │                                                else findFiles; then files.exclude and .git/node_modules. No folder-name blocklist.
  ├─ isSafeWebviewMessage()  [message_guard.ts]   rejects webview messages whose uri/relative paths leave the workspace.

  ├─ getHtml()               [webview_html.ts]    builds the webview page (markup, CSS, CSP, nonce'd scripts); re-exported from extension.ts for the screenshot script.

  ├─ EditorGroupTracker / decideF4 [editor_groups.ts] split-editor bookkeeping (return point, covered editor, bounded opens) and the F4 decision, over an injected facade; unit tested.
  ├─ isThumbviewViewType()   [webview_tabs.ts]    recognizes Thumbview's tab; the tab API reports viewType as "mainThreadWebview-thumbview".

Webview panel ("thumbview")
  └─ postMessage("data" | "status" | "activeFile" | "openState" | "setFocusedFolder" | "hoverLines" | "hideForTransition" | "showAfterTransition") ──┐
                                                                                                        │
media/overview.js (webview/browser side)                                                               │
  ├─ Receives data payloads, pre-indexes file text into _combinedText buffer for single-pass search,   │
  ├─ Pre-tokenizes lines on payload receipt and caches tokenized HTML (_htmlCache),                   │

  ├─ Dims non-selected files (opacity 0.15) when a directory or 'Root Directory Files Only' is focused, │
```

### Cross-module interface

The `postMessage` protocol uses string literals matched between `extension.ts` and `media/overview.js`: `"data"`, `"status"`, `"activeFile"`, `"openState"`, `"setFocusedFolder"`, `"hoverLines"`, `"hideForTransition"`, `"showAfterTransition"`, `"ready"`, `"jump"`, `"switchTab"`, `"close"`, `"getHoverLines"`, `"focusWindow"`, `"openPreview"`, `"openToSide"`, `"revealInFiles"`, `"openContainingFolder"`, `"renameFile"`, `"deleteFile"`, `"ignoreFile"`, `"copyPath"`, `"copyRelativePath"`, `"copyFile"`, `"cutFile"`, `"selectForCompare"`, `"compareWithSelected"`, `"reorderFile"`, `"setDragReorderMode"`, `"setLayoutMode"`, `"setRenderMediaThumbnails"`, `"reflow"`, `"addIgnorePattern"`, `"removeIgnorePattern"`, and `"saveLayoutOrder"` (`{ scope: "folderFiles" | "folderCards" | "rootCards", folder, ids, footprints?, wrapRows?, flowCells? }`). `"panelHidden"` (host to webview, no fields) reports that the panel was backgrounded. `data` carries `showShortcutLegend` (the in-grid key legend until the webview posts `"dismissShortcutLegend"`, stored as `thumbview.shortcutLegendDismissed`). `"fullscreenNotice"` (host to webview, `{ keybinding }`) shows the one-time fullscreen banner, and `"fullscreenSetting"` (`{ enabled }`) syncs the Settings toggle after the setting changes; the webview answers `"dismissFullscreenNotice"` or `"setFullscreenOnOpen"` (`{ enabled }`, also sent by the Settings toggle; `data` carries `fullscreenOnOpen`). `"requestFileLines"` (`{ ids }`) asks the host to resend files whose lines a delta payload omitted. `"hideForTransition"` and `"showAfterTransition"` carry `{ transitionId }`, and `"data"` carries per-file `contentVersion` plus, in spanning mode, `naturalCells`, `slotFootprints`, and `slotFlowCells`. When adding a command or changing its shape, note its fields in a short comment at both ends. File and settings commands are entries in the handler tables of `file_actions.ts` and `settings_actions.ts` (each receives what it needs through a small host interface); `onDidReceiveMessage` dispatches to those tables before the remaining inline handlers (layout, jump, transitions), which stay in `extension.ts` because they share its panel and layout state.

### Non-obvious details

- **Shared layout core.** `buildStableGrid`, `cellsNeeded`, `fillLayoutHoles`, `clampTargetToGridCapacity`, and the spanning `expand`/`reduce`/`reorderSpanningItems` live only in `src/layout_core.ts`; `layout.ts`, `spanning_layout.ts`, `state.ts`, and `reorder_helpers.ts` re-export them, and `scripts/sync-webview-core.mjs` generates them into `media/overview.js`. The webview calls `buildStableGrid` with an explicit aspect (`BASE_GRID_ASPECT`) and `cellsNeeded` with `getCompressionPct()`. The tokenizers exist only in the webview. See DESIGN.md.
- **Search regex and whole-word patterns are duplicated.** Keep `media/overview.js`'s `rebuildSearchState()` and `extension.ts`'s `"jump"` handler synchronized by hand.
- **Parallel repository scanning and sorting.** `scanner.ts` scans workspace files in parallel batches of 50 with `Promise.all()` and sorts them alphabetically by relative path so sibling files sit adjacent in the grid.
- **View frustum culling.** Cards outside the viewport are skipped during canvas render loops.
- **Subdirectory focus dimming.** Focusing a folder dims non-focused files to opacity 0.15 without hiding them, keeping grid positions stable.
- **Maximum line pitch.** Line spacing (`stepY`) is capped at 16px max so short files do not stretch lines across the card.
- **Media aspect ratio preservation.** `drawAspectFit` in `media/overview.js` scales images and PDF Page 1 snapshots using contain logic, preserving natural aspect ratios inside grid tiles. `imageCache` clears on repository data updates, and image URIs append a timestamp query parameter (`?v=timestamp`) so edited images refresh on disk changes.
- **Pre-computed indexing and tokenization.** Search runs through `textMatches()`, backed by `rebuildSearchState()`. Plain matching stays on the pre-lowercased path (`file._combinedText.includes(searchQuery)`), or `file._combinedTextOriginal.includes(rawSearchQuery)` when Match Case is on. Whole Word and Regular Expression compile a `RegExp` against the original-case text. An invalid regex sets `searchInvalid` so callers treat tiles as non-matching rather than throwing. Line HTML syntax spans are cached in `line._htmlCache`. Search highlighting is rebuilt fresh via `buildLineHtml()` on each hover render because the query or toggles can change between hovers of the same cached line.
- **Top-level ignore consolidation.** Auto-ignore consolidates dense folders to top-level root paths (such as `BOFS/`) and prunes child subdirectories to prevent tree bloat. Folders listed in `autoIgnoreExclusions` (workspaceState) are never auto-ignored.
- **Ignore state in workspaceState.** `ignorePatterns` and `autoIgnoreExclusions` live in `ExtensionContext.workspaceState`, not in `.vscode/settings.json`. Old settings.json values migrate on first activation.
- **Multi-select tree view.** `thumbview-ignores` enables `canSelectMany: true` for Shift and Ctrl batch deletions and unignores.
- **Left CTRL hover inspection.** The magnifying overlay requires holding `Left CTRL`, throttles position updates with `requestAnimationFrame`, and fixes overlay width to `min(maxWidthAllowed, widestLine)` per file to prevent tooltip box jitter while moving across lines.
- **Automatic webview DOM focus.** `extension.ts` sends a `focusWebview` message, and `media/overview.js` calls `window.focus()` on load so `Left CTRL` hover and search typing work immediately. Background IPC messages (`data` and `openState`) do not invoke `window.focus()`, avoiding focus stealing while typing in text editors.
- **Fullscreen mode through Zen mode.** Opening Thumbview runs `workbench.action.toggleZenMode`, which snapshots and restores sidebar, panel, and aux bar visibility. Extensions cannot read workbench visibility state directly. Zen settings `zenMode.centerLayout`, `zenMode.fullScreen`, `zenMode.hideActivityBar`, and `zenMode.hideLineNumbers` are temporarily set to false and `zenMode.showTabs` to `"none"`; split editors are hidden by maximizing Thumbview's group. Only keys the running VS Code registers are written (writing an unregistered key throws; `zenMode.singleTabGroup` does not exist and once silently prevented Zen from ever being entered), writes use `Promise.allSettled`, and `enterFullscreen` runs `toggleZenMode` in its own `try` so a settings failure can never keep Thumbview out of fullscreen. Nothing is written at activation. `ensureZenOverrides` applies them once per session, on the first fullscreen open (`applyZenOverrides` backs up the user's global values in `globalState` as `thumbview.zenSettingsBackup`), so toggling never rewrites settings.json. Each window using them is an owner under its own `globalState` key (`thumbview.zenOwner.<sessionId>`, one key per window so concurrent claims cannot clobber each other) with a 30s heartbeat; `releaseZenOwnership` restores the user's values only when the last live owner leaves (every `deactivate()` releases its own key, even if it never opened Thumbview), so a second window cannot undo the first. Activation recovery (`recoverZenSettings`) re-checks after `ZEN_OWNER_STALE_MS` when another owner still looks live, because a reload or crash leaves the previous session's heartbeat fresh for up to 90s. Crash recovery also exits a Zen mode Thumbview left on (`thumbview.zenEnteredByThumbview`). Zen entry is still a blind `toggleZenMode` (extensions cannot read Zen state), but Thumbview only exits a Zen mode it entered. `thumbview.fullscreenOnOpen` (default true) disables Zen and maximize entirely. The sidebar remains hidden during Zen mode. Actions, settings, directory navigation, and ignored pattern management live in the webview toolbar and settings modal. Every Zen and maximize layout sequence (open/close through `thumbview.open`, `closeActiveThumbview`, `jump`, `switchTab`, and the view-state exit) runs under `withLayoutLock` (a re-entrant promise queue from `locks.ts`), and `thumbview.open` goes through `createCoalescedToggle`, so presses during a toggle are coalesced by parity instead of stacking blind `toggleZenMode` calls. Both have a 5s watchdog (`LOCK_WATCHDOG_MS`) so a workbench command that never resolves cannot swallow F4 forever. Timer callbacks created inside a locked task run through `detachFromLocks()` (`lock.exit`) so they do not inherit lock ownership, and `panel.onDidDispose` runs under the layout lock. F4's decision is `decideF4` (`editor_groups.ts`): close only a focused Thumbview; a visible but unfocused one (beside the code in a split, or with the terminal focused) is focused where it is (`reveal(panel.viewColumn)`, never moved over the code; the user's choice for tab mode); in fullscreen mode one that is not fullscreen yet is reopened in its own group. Each F4 logs the panel state to the Thumbview output channel. The toggle trusts its own last intent for 1s (`TOGGLE_INTENT_TRUST_MS`) because `panel.active` lags `reveal()`. Both the create and reopen paths count as layout ops (`layoutOpsInFlight`), and the view-state handler's "dragged into a split" close ignores groups Thumbview maximized itself; without both, the first open with split editors closed the new panel immediately. The view-state handler ignores events while a layout operation is in flight and exits only when the panel is hidden. Zen is entered before the panel is created or revealed. The reopen path has no fixed sleeps: it waits for the panel's view-state event (`waitForPanelActive`, bounded) and relies on the webview's stable-size gate. On reopen the retained panel is revealed *before* the group is maximized (`waitForPanelActive`), because `toggleMaximizeEditorGroup` acts on the active group, which right after a split is not the one holding the panel. On toggle-off the webview content is hidden with `hideForTransition` (setting `body.opacity` to 0) and Zen exits. `jump` and `switchTab` instead load the document first (`openTextDocument`, no visible change), then `switchLeavingFullscreen()` sends the Zen exit, the unmaximize, and `showTextDocument` back to back without awaiting in between (all settled inside the lock; failures are shown and logged; `openState` posts are held meanwhile via `openStateHeldForSwitch`, released whenever the panel becomes visible by any route, on panel creation, or by a failed open; each open's timing is logged to the "Thumbview" output channel), so the file appears once, already in the normal layout, rather than first in Zen and again when the layout is restored; no hide and no fixed sleeps. `beginTransition(panel, { hide: false })` still supersedes older transition ids. The first fullscreen open shows a one-time banner inside Thumbview (`maybeShowFullscreenNotice`, `globalState` `thumbview.fullscreenNoticeShown`, recorded when sent; hidden on `panelHidden`) rather than a VS Code notification, because Zen's default `zenMode.silentNotifications` hides notifications. "Open as a tab instead" writes `thumbview.fullscreenOnOpen = false`; the configuration listener then leaves fullscreen and syncs the toggle (`fullscreenSetting`), the same path as a `settings.json` edit.
- **Recursive subfolder card expansion.** When root grid cells fall below 60×40px, `media/overview.js` switches to subfolder card mode, grouping files by immediate child folder into clickable cards. Folder card previews display nested child folder cards only when opening the folder would collapse into cards, using the same row-major `buildStableGrid` layout as the drilldown view. If files will be laid out individually, the preview mirrors that layout with proportional spanning heights. Clicking drills down recursively until tiles are readable.
- **Zero-reflow window resizing.** `media/overview.js` uses a constant `BASE_GRID_ASPECT = 16 / 9` and reference canvas bounds (`REF_CANVAS_W = 1200`, `REF_CANVAS_H = 800`) for layout calculations so window resizing scales tile dimensions (`cellW` and `cellH`) without reflowing tiles into different columns and rows. When the window shrinks to where tiles become unreadable (`cellW < minCellWidth || cellH < minCellHeight`), views containing subdirectories collapse into folder thumbnail cards.
- **Folder card rearranging and column bounds.** In folder cards mode, `buildStableGrid` allocates capacity based on `Math.max(orderedItems.length, displayItems.length)`, creating rows and slots for cards dropped into empty rows below. Folder card reordering inside folders (`swapCardItems`) updates `thumbview.folderCardOrders[folder]` without mutating file-level `thumbview.folderOrders[folder]` or global `fileOrder`. Dragging tiles rightward strictly bounds columns to `targetGridCols` without adding `extraCols` twice. Right-clicking "Expand Grid Space" is the sole mechanism for expanding grid columns.
- **2D spanning drag reordering.** `media/overview.js` runs `reorderSpanningItems` (shared core) directly on `mouseup`, keeping untouched files in adjacent rows and columns locked to their exact coordinates and rendering the moved file at its target slot. Extension host IPC messages dispatch synchronously before disk state persistence.
- **Mouse button navigation.** Mouse buttons 3 (Back) and 4 (Forward) are handled exclusively in `mouseup`. Duplicate triggers are suppressed in `auxclick` to ensure one step of navigation per physical click.
- **Centralized UI theme colors and brand accents.** UI chrome colors derive from VS Code theme contribution points (`--vscode-editor-background`, `--vscode-foreground`, `--vscode-menu-*`, `--vscode-focusBorder`). Three fixed brand accents are defined in `src/colors.ts`: `ACCENT_SEARCH = "#dc267f"`, `ACCENT_INSPECT = "#785ef0"`, and `ACCENT_RECENCY = "#fe6100"`. The host injects them into the webview style element as CSS variables, which `media/overview.js` reads with `getThemeColor("--tv-accent-*")`.
- **Hover outline and `findFileAt`.** Hovering any tile draws a light-blue outline using `BORDER_STYLES.dragging`. The module-level `hoveredFile` resolves through `findFileAt(px, py)` on every `mousemove`. This is an exact hit test, unlike `findNearestSlot` which resolves to a `{col, row}` slot. The same color and outline style are reused for the drag ghost and drop-target outline so all three read as one consistent interaction state. Inside a focused folder, `findFileAt` tests against `activeRenderGrid.files` directly instead of iterating all workspace files.
- **Retained webview context.** `createWebviewPanel` sets `retainContextWhenHidden: true`. When Thumbview closes through `F4`, `Esc`, `jump`, or `switchTab`, the panel is backgrounded rather than disposed. Re-opening Thumbview reveals the live panel instantly without DOM re-initialization.
- **Monospace character width arithmetic.** `drawThumbnail` computes text layout using single-sample monospace font width caching (`getMonospaceCharWidth(fontSize)`), calculating token advance in $O(1)$ arithmetic (`tok.text.length * charWidth`) without calling `ctx.measureText`.
- **Tile raster caching and memoized mini-mosaics.** Code tiles render to offscreen canvases and cache in `tileRasterCache` (500 entries max), drawing cached tiles with editor viewports rendered dynamically on top. Subfolder mini-mosaics are memoized to offscreen canvases in the module-level `mosaicCache` Map. It is not stored on the group object because `getSubfolderGroups()` rebuilds groups every render. `applyDataMessage` clears it.
- **Single viewport source and render coalescing.** A `ResizeObserver` on the canvas is the only source of canvas size (`getViewportW()`/`getViewportH()`). Do not read `window.innerWidth` or `canvas.clientWidth` for layout. Host messages and resizes call `scheduleRender()` (one render per animation frame). Interactive paths that need synchronous hit-test geometry call `render()` directly.
- **Stretch on resize.** The `ResizeObserver` callback calls `stretchLastFrameToViewport()` before paint so a size change never shows the old frame in the top-left corner, then schedules the sharp render.
- **Transition ids.** `beginTransition()`/`endTransition()` in `extension.ts` tag every hide/show with an increasing `transitionId`; `endTransition` only sends for the latest id. The webview ignores messages older than the newest id it has seen (`isStaleTransition`), so a delayed show from a previous close cannot reveal a later open.
- **Stable-size reveal gate.** The webview starts at `opacity: 0` (initial CSS in `getHtml`) and `hideForTransition` re-arms the same gate (`armReveal()`). The page reveals itself only after a data render whose viewport size holds for two frames (`checkRevealStable`). After `hideForTransition`, the check is also blocked (`revealBlockedByTransition`) until the current transition's `showAfterTransition` arrives. Becoming visible only restarts the safety timer, and key or pointer input reveals only when no transition is in flight (spamming F4 sends keydowns to the focused webview mid-expansion). Fallbacks: loading status at 400ms on first open, and `revealSafetyTimer` (2.5s first open, 1.5s after a transition). While backgrounded it polls every 500ms instead of relying on `visibilitychange`, and after becoming visible it restarts the full delay so it cannot reveal mid-reopen. While `revealPending` is true, `ensureVisibleOpacity()` is a no-op. A transition that ends below 200px reveals the "Enlarge the panel" hint rather than staying blank.
- **Spatial stability is the product.** Files must never change position when others are ignored, deleted, added, or unignored. Every order (root `fileOrder`, `thumbview.folderOrders`, `thumbview.folderCardOrders`, `thumbview.cardOrder`) goes through `fillLayoutHoles` (shared core, `src/layout_core.ts`): a removed id stays as a hole, a new item fills the earliest hole it fits in, and only then appends. `""` entries are user gaps and are never filled. Never trim or compact orders; only Reflow Layout compacts.
- **Spanning holes keep their size.** A hole's size is the removed id's cells in that view: `naturalCells` (host-persisted, kept for removed ids) or its footprint there. An item that fills a taller hole records a footprint (`thumbview.slotFootprints`, scoped `"root"`, `"folder:<path>"`, `"cards:<path>"`) and is laid out at `max(natural, footprint)` cells, so it occupies exactly the hole and no column break changes. Footprints are scoped so a fill in one view never grows the file in another. The first spanning reconcile of a folder or card view freezes its column height (`folderWrapRows`, `folderCardWrapRows`, `cardWrapRows`) so appends add columns instead of re-wrapping.
- **Growth never changes columns.** Spanning layouts separate frozen *flow cells* (column membership; root `thumbview.spanningAllocations`, webview scopes `thumbview.slotFlowCells`) from *display cells* (current `cellsNeeded`, at least the footprint). A growing or shrinking file shifts files within its column only; an overflowing column adds rows and proportional columns. `buildSpanningGrid(…, displayCells)` and `buildSpanningGridLocal(…, footprints, flowCells)` implement the same split — keep them in sync. Both return `flowRows`/`flowCols` (the pre-overflow size); folder-card collapse checks (`rootCellsTooSmall`, `doesFolderCollapse`, folder `refFolderCellW/H`) use those so typing can never flip a view into cards. Every drag simulation builds its cell map with `dragFlowAllocations(scopeKey, …)` (webview) or the scope's frozen flow cells (host `reorderFile`), never display heights; the payload's `slotFlowCells.root` carries the host's root flow cells for this. `thumbview.naturalCells` is recorded in both layout modes so holes size correctly after a mode switch.
- **Webview owns folder and card reconciliation.** Only the webview knows those layouts, so `reconcileFolderFileOrder()` and the card-mode block reconcile on render (seeding the on-screen order on first view) and post `saveLayoutOrder`, mirroring the result into `data` immediately. The host only stores it. The root order is reconciled on the host in `updateLayoutFromCacheLocked`.
- **Order write lock.** Every read-modify-write of persisted orders (payload building, `saveLayoutOrder`, `reorderFile`, `reorderFolder`, `swapCardItems`) runs inside `withOrderLock()`, a promise queue made re-entrant with `AsyncLocalStorage` so a handler that calls `updateLayoutFromCache` does not deadlock.
- **Settling after layout ops.** `releaseLayoutOp()` decrements `layoutOpsInFlight` 400ms late and, on the last release with Thumbview visible, sends `endTransition` so a quick return to the tab is not left hidden. After a transition the webview also requires the size to hold for `TRANSITION_REVEAL_STABLE_MS` (120ms) before revealing.
- **F4 and the keybinding label.** The `thumbview.open` binding has `"when": "!searchViewletFocus && !referenceSearchVisible"` so VS Code's own F4 wins while the Search view has focus or a references peek is open. Deliberately not `!hasSearchResult`: lingering search results would make F4 appear to stop opening Thumbview (user's choice). The toolbar label comes from the nearest `keybindings.json` above the extension's `globalStorageUri` (covers default and per-profile layouts; absent under Remote, which falls back to "F4"), cached by mtime; do not probe other paths.
- **Recognizing Thumbview's tab.** Always use `isThumbviewTab` / `isThumbviewViewType` (`webview_tabs.ts`). The tab API reports an extension webview's viewType as `mainThreadWebview-thumbview`; the old comparison with `"thumbview"` never matched, so every split-editor fallback that looked for Thumbview's tab silently did nothing.
- **Split sizes.** `unmaximizeIfSplits` does nothing unless Thumbview maximized a group (`groupMaximizedByUs`); after undoing that maximize it evens split editor widths (`workbench.action.evenEditorWidths`). Both are the owner's decisions: maximize/unmaximize does not restore sizes reliably (keeping proportions left groups tiny or unreadable), and in tab mode, where nothing was maximized, widths are never touched. Do not change either.
- **Close in one visual step.** Like `jump`, the close path dispatches the Zen exit, the unmaximize, and `editorGroups.returnToEditor()` back to back and settles them together (`Promise.allSettled`), so the file appears in the restored layout without an intermediate frame; `onDidDispose` also leaves Zen before unmaximizing.
- **Split editors on close.** `closeActiveThumbviewLocked` first returns to the tracker's return point (`editorGroups.returnToEditor()`): the file and group the user was in when F4 opened Thumbview, re-recorded when Thumbview is shown by a tab click or Ctrl+Tab, and cleared after a jump and after each close, not to `lastActiveTextEditor`, which Thumbview's own Zen/maximize steps can change and whose `viewColumn` is lost while hidden. If Thumbview still shows in a group after that, `restoreCoveredEditor` then re-shows, without focus, the editor Thumbview covered in its own group (`coveredEditor`, recorded from a pre-reveal/pre-create snapshot of each group's active editor, keyed by the active group's column on create because `panel.viewColumn` is unresolved until the first view-state event), falling back to that group's first other editor, so no group is left showing Thumbview.
- **Host source in tests.** Tests that check host code or page markup by text read `readHostSource()` (`src/test/helpers/host_source.js`: `extension.ts` plus `webview_html.ts`); add new host modules there when they hold checked text.
- **Switch freeze.** `postSwitchAway` (every `jump`/`switchTab` post) sets `switchingAway`, which `isFrameFrozen` honors, so the grid does not repaint while VS Code rebuilds its layout around the newly opened file. It ends on `panelHidden` (the hidden-panel freeze takes over), on reopen (`markPanelShown`), on any keydown or pointerdown (capture phase), or after `SWITCH_FREEZE_MAX_MS` (2s) if the open failed.
- **Fast reopen (no black flash).** While a transition hides a previously shown page, `render()` and the resize stretch are frozen (`isFrameFrozen`), so the canvas keeps the last frame the user saw (`lastRevealedW/H`, updated by every visible render and by `completeReveal`). `tryFastReveal` shows it immediately when the page is visible again at exactly that size (the reopen sends `hideForTransition { fromHidden: true }`, and drawing also stays frozen while `panelHiddenByHost`, so a jump that never hid the page still keeps a valid frame), but only after the panel was actually hidden (`hiddenSinceArm`, set by the host's `panelHidden` message from `onDidChangeViewState` because retained webviews may be hidden without `document.visibilityState` changing), so a close never reveals mid-exit. Otherwise the normal gate applies. Every `completeReveal()` schedules a render, because a fallback reveal can happen while drawing was frozen at an old size.
- **HiDPI rasters.** Tile and mosaic rasters are `intW * dpr` by `intH * dpr` (dpr capped at 2), drawn with explicit width/height; dpr is in both cache keys.
- **Resize keeps raster caches, bounded by bytes.** `resize()` does not clear `tileRasterCache` or `mosaicCache`; their keys include pixel size and the search toggles. Both are `CanvasLRU`s bounded by entry count and pixel memory (64MB tiles, 32MB mosaics), refresh recency on `get`, and shrink evicted canvases to 0x0 to release GPU-backed memory immediately. The resize snapshot canvas is released after each stretch.
- **Error-only diagnostics payloads.** The diagnostics listener posts a payload only when the error signature changes (`errorDiagnosticsSignature`); warnings and hints republished on every editor switch no longer trigger a full workspace payload.
- **Unsaved edits survive rescans.** `refreshThumbview` re-applies every dirty `TextDocument` via `updateDocumentInCache` after scanning disk.
- **Shared pre-scan and deferred hidden refreshes.** `ready` awaits the activation pre-scan (`prescanPromise`) instead of starting a second scan. Document edits (collected and applied once per 300ms pause) and diagnostics (500ms) are debounced and routed through `refreshOrDefer()`, which records `hiddenRefreshPending` while the retained panel is hidden and flushes it via `flushHiddenRefresh()` 250ms after reveal. Watcher events inside `.git` or `node_modules` (`isAlwaysExcluded`) are ignored; other events (e.g. a gitignored `out/` written by `npm run watch`) reach the debounced rescan, and `refreshThumbview(panel, true)` posts nothing when the scan returns the identical `RepoFile` objects (`lastRawScan`). A save produces one payload: the rescan awaits the save's git diff fetch.
- **Scan limits.** `listWorkspaceFiles` honors both `files.exclude` and `search.exclude`. After auto-ignore (`thumbview.autoIgnoreThreshold`, the primary guard), `scanRepository` reads at most `MAX_SCANNED_FILES` (10,000) files and warns once per session. Files already on the map (`setScanPriorityProvider`, fed with the persisted layout order) are kept first so the cap never makes a shown tile disappear because unrelated files were added.
- **Deletes.** All delete paths go through `askDeleteMode`: Move to Trash first; a permanent delete needs a second confirmation.
- **Accessibility.** The canvas is one focusable `role="application"` widget; there is no DOM element per tile. `keyboardTargets()` lists the drawn file tiles and folder cards; arrows move focus spatially (`neighborInDirection`), Home/End by reading order, Enter reuses the `jump` message or drills in, Shift+F10 and Alt+Arrow dispatch synthetic `contextmenu` and drag mouse events (`dispatchPointer`) so they share the mouse code paths. Focusing a tile sets `hoveredFile` and `lastMousePos`, so the Ctrl magnifier and Ctrl+C/X/Delete act on it. `render()` wraps `renderScene()` and then draws the focus ring (`drawKeyboardFocus`). `announce()` writes to the polite `#sr-status` region (focused tile, search counts via `scheduleSearchAnnouncement`, folder changes, errors). Printable keys still go to search, so never bind a character key to grid navigation; the one exception is Space, which activates the keyboard-focused tile while keyboard focus is shown. Space on a focused `<button>` presses it rather than typing into search. Dialogs have `role="dialog"`, `openToolbarDialog`/`closeAllPopovers` move and restore focus, and the settings modal traps Tab. The page has a `<title>`, a `role="main"` container with a visually hidden `<h1>`, a `role="search"` search box, and every settings control is labelled (`aria-labelledby` its setting name); `npm run test:a11y` (axe-core, WCAG 2.1 AA) must stay clean. Tiles show `tileStatusBadge` text (e.g. `2, M`) besides color.
- **Delta payloads.** `withDeltaLines` sends each file's `lines` as plain strings (about half the size and several times faster to clone than line objects), and `applyDataMessage` wraps them back into `{ text }` objects that carry the render caches; it accepts either form. A line's `indent`, `length`, and `category` are derived from its text on first draw by `lineShape()` (tile indentation and folder-preview bars read them; `categorizeLine` lives in the shared core), and per-line lowercase copies by `lowerLineText()`. Any new reader of those fields must go through `lineShape()`. It sends a file's `lines`/`fullLines` only when its `contentVersion` differs from what the webview holds (`postedContentVersions`, reset on `ready`); otherwise `linesOmitted: true`. `applyDataMessage` reuses the previous line objects (keeping token caches) and posts `requestFileLines { ids }` for anything it lacks, which makes the host resend those files. Raster caches are no longer cleared per payload: tile keys include `contentVersion` and `_decoSig` (hash of git status/changes and error lines), mosaic keys `groupMosaicSignature(group)`.
- **Output channel.** `log` ("Thumbview", a LogOutputChannel) records the initial scan time, webview scan wait, each data payload's build and delivery time (first per panel at info, later at debug), every F4 decision, the split-editor trace, and each file open's timing. Use it for user reports; never log file contents.
- **Onboarding.** `contributes.walkthroughs` ("Get started with Thumbview", Markdown in `media/walkthrough/`) plus the dismissible in-grid shortcut legend.
- **Security.** Every webview message goes through `isSafeWebviewMessage` first (with `isUriInsideWorkspace`, which compares resolved real paths for `file:` URIs); it also rejects any `uri` with a raw or percent-encoded `..` segment (`hasDotDotSegment`), because VS Code's URI parser does not normalize dot segments and `getWorkspaceFolder` would accept them. The CSP has no `'unsafe-eval'` and `script-src` is the page nonce only (no host source, so a file in a workspace folder can never run as a page script even if markup were injected); the on-demand pdf.js loader sets `script.nonce` from `window.PDF_JS_NONCE`. pdf.js runs with `isEvalSupported: false`. Every workspace-controlled string placed in HTML goes through `escapeHtml` (webview) or the host's `escapeHtml` in `webview_html.ts` (the key label). Names typed into New File, New Folder, and Rename go through `typedPathInside` (no absolute paths, no `..`); `setLayoutMode`/`setDragReorderMode` accept only their enum values. In Restricted Mode git never runs (file listing falls back to `findFiles`, no git markers) because a repository's config can execute commands; `package.json` declares limited `untrustedWorkspaces` and `virtualWorkspaces` support. Non-`file:` URIs are read only through `vscode.workspace.fs`.
- **Content-versioned search index.** Each payload file carries `contentVersion` (host `WeakMap` over `RepoFile` object identity). `fileTokenCache` is keyed by file id and reused only when `contentVersion` matches; ids missing from the payload are evicted.
- **Surgical file invalidation.** `invalidateScanFile(filePath)` evicts only modified files upon watcher events, and `DirectoryTreeDataProvider` consumes cached scan data.

## Terminology

The extension was renamed from **Repository Map** (`repomap`) to **Thumbview** partway through development. Every user-facing surface uses **Thumbview**. Internal state keys use the `thumbview.*` prefix (`"thumbview.seenFiles"`, `"thumbview.spanningAllocations"`, `"thumbview.spanningRows"`, `"thumbview.zenSettingsBackup"`). A one-time migration in `extension.ts` copies values from the old `repomap.*` keys on activation and deletes them. See DESIGN.md.

## Committing changes

**Do not commit unless explicitly asked.** Never offer to commit or prepare a commit message speculatively.

- Match recent repository conventions in `git log -n 5`.
- Keep bug fixes and performance refactors clearly demarcated in commit summaries.

## Branch workflow

Development takes place on personal dev branches (such as `bobby-dev`). Work is committed to the dev branch, merged into `main`, and pushed only when explicitly requested by the user.

## Responding to a reported problem, issue, or bug

When the user reports a problem, issue, or bug:
1. Investigate and pinpoint the actual root cause first.
2. Explain the cause to the user.
3. Explain your proposed solution.
4. Wait for the user's explicit approval before making any edits.

## Verifying UI and layout changes

README images come from `scripts/capture-screenshots.mjs`, which renders the real `getHtml` page and `media/overview.js` in headless Chrome with a host-shaped payload; regenerate them when the UI changes visibly. That script is for documentation, not verification: never attempt to launch F5 or visually verify canvas and webview changes yourself. Make the change and ask the user to press F5 to test. Do not run `npm run compile` or `npm run lint` proactively unless explicitly requested by the user. Do run the no-output type check `tsc --noEmit -p ./` after TypeScript edits and fix what it reports before handing work back: the esbuild bundle and the node unit tests do not type check, so type errors otherwise reach F5 or CI.
